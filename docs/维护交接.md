## UDP 数据路径

GUI → CytonManager → WiFiUDPBoard → HTTP 配置 Shield → 电脑 UDP 接收 → 解码 → 滤波/显示/保存。

HTTP 控制包括 `/board`、`/udp`、`/command`、`/stream/start`、`/stream/stop`。连接时读取 `/tcp` 判断冲突，拒绝已有 TCP 客户端；串口和模拟板继续使用 BrainFlow。

UDP 使用 raw 数据，关闭 delimiter 和 redundancy，latency 为 10000 μs。本地路由选出的 IPv4 地址用于绑定，默认接收端口 6677；socket 接收缓冲申请 1 MB，应用环形缓冲 60000 帧。

帧为 33 字节：`A0`、8 位计数器、8 × 有符号 24 位 ADC、6 字节辅助数据、`C0..C6` 尾字节。每个数据报独立解析，损坏数据不跨报文拼接。单位换算为 `counts × 4.5e6 / ((2**23-1) × gain)` μV；成功的 `x...X` 通道设置命令更新增益，包含阻抗检测切换。

## 必须保留的连接修复

设置 1000 Hz 时发送 `~4` 并解析返回的 `Success: Sample rate is 1000Hz`。早期 UDP 版本额外发送了不支持的 `~?`，实板返回 `Failure: invalid sample value`，导致连接失败。当前版本已移除；不要重新加入 `~?`。`test_wifi_udp.py` 中 Fake Shield 覆盖该行为。

相对原 TCP 源码，UDP 主要涉及 `board_manager.py`、`config_viewer.py`、`main.py`、`ui/main_window.py` 及新增 `wifi_udp.py`。本次源码交付整理没有重构应用逻辑；新增的是交付文档、环境文件和辅助脚本。

## 维护检查

修改 UDP 连接、帧解析、增益或启停后，先跑全部测试及 selftest，再用实板检查连接、采样率、8 通道和断开释放。修改 GUI 或同步流程时，另检查模拟板 GUI 和实际外围硬件；自动测试使用模拟或替身，不能代表实际同步精度。

`verify_gui.py` 用模拟板生成离屏截图。`verify_capture.py 诊断会话目录` 需要 `raw.bin`、`chunks.csv`、`samples.csv`，仅用于回放旧的 250 Hz 诊断格式，不是 1000 Hz 稳定性测试。原始诊断数据不随源码交付。
